# 悪態独り 開発プラン（v0.1 / designer → worker向け）

前提: `draft/企画書.md` を先に読むこと。仕様の数値はすべて企画書 §5 に従う。

## 1. 技術選定
| 項目 | 選定 | 理由 |
|---|---|---|
| 描画 | 素の Canvas 2D | 参考作（虫アプリ_ver4）と同方式。320×180のドット絵なら十分。Phaser等は不要（物理も多数のスプライトもない） |
| 音 | 素の Web Audio API | 判定とBGMを同じ `AudioContext.currentTime` で揃えられる。Tone.js は不要（過去にオフライン書き出しで落とし穴あり: knowledge/web-dev/Tone.js…） |
| 言語/構成 | 素の JS、**クラシック `<script>`（ES modules を使わない）**、ビルドなし | ES modules は file:// で動かない（ver4 は起動.batでサーバーを立てていた）。ダブルクリックで遊べる方が爆速で確認できる。グローバルは `window.AT`（悪態）1つにまとめる |
| フォント | Google Fonts `DotGothic16` | ver4 踏襲。オフライン時は日本語フォールバック |
| データ | 回顧文・結末文・曲は `.js` に書く（`AT.TEXTS = {...}`） | file:// では fetch でJSON/txtを読めないため |

## 2. ファイル構成（ゲーム本体は `output/` に置く。Pages でこのフォルダだけ公開する想定）
```
output/
  index.html        … canvas + #ui オーバーレイ + script読み込み（順番固定）
  src/
    core.js         … AT 名前空間、定数(W=320,H=180)、PALETTE、ユーティリティ、乱数
    input.js        … キー/ポインタ → AT.input.onHit(cb)、e.repeat無視、最初の操作でAudioContext resume
    audio.js        … AudioContext、マスター、lowpass(スロー用)、スケジューラ(先読み)、モーグ風音色、ドラム
    songs.js        … 曲データ（旋律・和音・BPM範囲）。差し替え口 AT.MUSIC
    rhythm.js       … ノーツ生成、判定、speed、bpm更新、成績記録
    art.js          … パレット番号配列→canvas 変換、スプライト・背景生成
    scenes.js       … シーン状態機械（title/walk/attack/recall/warp/run/flash/ending）
    ui.js           … #ui の文字表示（独り言、回顧文1文字ずつ、叫び、判定、メーター、結末）
    main.js         … ループ(requestAnimationFrame)、dt、timeScale、起動
  data/
    texts.js        … 回顧文・独り言・結末文（draft/回顧文_下書き.md から転記）
    rounds.js       … 3ラウンドの組（襲来物/異世界/曲/BPM/差し色）
  audio/            … （将来）差し替え用音源ファイル置き場
```

### 音源差し替えの構造（必須で入れておく）
`data/rounds.js` の各ラウンドに `music` を持たせ、audio.js は種類で分岐する。
```js
music: { type: 'synth', song: 'tell' }                         // 既定: 自作シンセ
music: { type: 'file', src: 'audio/r1.mp3', bpm: 120, offset: 0.08 } // 差し替え時
```
- file の場合: テンポ上昇は `playbackRate = bpm/bpmBase`（ピッチも上がる＝早回し。演出として可）。判定グリッドは `offset + 拍数×60/bpm` で計算。
- synth の場合: 小節頭でBPMを変えてスケジュール。

## 3. タスク（依存順。T1〜T4 が最小の縦切り）
各タスク終了ごとに `git add` → `commit`（push はしない）。

### T1 土台 【縦切り】
- 内容: `output/index.html` と `core.js / input.js / main.js / scenes.js / ui.js` の骨組み。ver4 の index.html の CSS（16:9中央配置、pixelated、#ui、DotGothic16、縁取り text-shadow）を参考に**書き直す**（色は企画書§7の夜色に）。シーンは title → walk → attack → recall → warp → run → flash → (次ラウンド or ending) を仮表示（色付き矩形とシーン名の文字）で遷移。
- 完了条件: index.html をダブルクリック（file://）で開き、タップ/キーでタイトル→全シーンが順に遷移し、結末まで行ける。コンソールエラーなし。PCとスマホ幅で16:9が崩れない。

### T2 音の時計とリズム判定 【縦切り】
- 内容: `audio.js`（AudioContext、先読みスケジューラ: 25msごとに100ms先まで予約）、`rhythm.js`（企画書§5のノーツ・判定窓・speed・減衰・コンボ・小節頭BPM更新・60秒救済）。仮音はクリック音。run シーンにレーンと判定線、判定文字（PERFECT/GOOD/MISS）、速度メーター。
- 完了条件: ビートに合わせて叩くと PERFECT が出る／ずらすとGOOD・MISS。速度が上がるとクリックのテンポが上がる。100で flash へ遷移。叩かなくても75秒以内に flash へ行く。成績（accuracy, reachTime, assisted, maxCombo）が console に出る。

### T3 モーグ風シンセと1曲目 【縦切り】
- 内容: 音色 = ノコギリ波2本（±7セントでデチューン）→ lowpass（共振Q≈8、エンベロープでカットオフを開閉）→ ゲイン。ベース=矩形波1オクターブ下、ドラム=キック(サイン波のピッチ下降)・スネア(ノイズ+bandpass)・ハット(ノイズ+highpass)。曲の書式は ver4 の `songs.js` と同じ `"音名オクターブ:拍"` 形式（例 `"E5:0.5 r:0.5"`）、和音は小節ごと。
- 曲: 「スイス軍の行進」の主旋律（8〜16小節のループ）。**旋律は PD の楽譜（IMSLP 等）から書き起こし、照合できなかった箇所は曲データのコメントに「未照合」と書く**（ver4 と同じ扱い）。既存の電子編曲・録音を写さない。
- ドラムの4分キックがノーツと一致すること（判定は音楽に対して取る）。
- 完了条件: run シーンでテル序曲が鳴り、テンポ上昇で早くなる。recall シーン中は lowpass が下がりこもった音になる。

### T4 R1 の絵と回顧文 【縦切り完成】
- 内容: `art.js`（パレット番号配列→canvas変換。ver4 pixelart.js の方式を参考に新規）。夜道背景（3層パララックス: 空と月 / 家並みと街灯 / 歩道）、主人公（歩き4コマ・走り4コマ、16×24程度）、ハクチョウ（滑空2コマ、32×24程度）、アルル背景（渦巻く星空・糸杉・黄色いカフェ、4層）。`ui.js` に回顧文の1文字ずつ表示（40ms/字、行送りはタップ or 2.5秒）と叫びの巨大文字（震え）。`data/texts.js` に R1 候補を転記しランダム選択。
- 完了条件: R1 だけで A〜F が企画書通りに通しで遊べる。→ **ここでユーザーに見せる（designer が見た目レビュー）**。

### T5 R2・R3
- 内容: 騎馬武者＋合戦場、紙飛行機＋高校の廊下（廊下は一点透視の擬似3D: 床の線と教室札を中心から拡大）。曲: 威風堂々第1番（トリオ主題）、歓喜の歌（行進曲風アレンジ）。テキスト転記。
- 完了条件: 3ラウンド通しで約5分、各ラウンドの曲・背景・差し色が違う。

### T6 結末
- 内容: 企画書§6のスコア計算と4段階分岐、玄関の絵、一言、成績、「もういちど」。
- 完了条件: わざと叩かない/全力で叩く、で別の結末が出る。

### T7 演出の仕上げ
- 内容: スローの青黒オーバーレイ、warp の渦（中心からの極座標ずらし）、疾走中の残像・色相回転、白光（白→無音1秒→フェード）、画面揺れ。帰り道の環境音（足音、遠くの車）。
- 完了条件: designer レビューで OK。

### T8（余裕） パーセル曲（タイトル/結末）、キャリブレーション、file 音源差し替えの動作確認、独り言のランダム生成。

## 4. 確認方法
- 主: file:// でダブルクリック。スマホ確認は簡易サーバー（`npx serve output` 等）＋同一LAN。
- リズムのずれ確認: 判定時のずれ(ms)を debug 表示（`?debug` クエリで表示）。
