### 主な統合判断（理由つき）
| 内容 | 理由 |
|---|---|
| 曲は `AT.SONGS` に統一。`AT.MUSIC` は同じオブジェクトの別名 | 曲担当3者が全員 AT.SONGS に置いたため |
| `songs.js` でドラム書式を16分グリッドの文字列に正規化。audio_engine に `Z`(K+S)/`W`(K+S+H) を追加 | ode は `"K:1 S:1"`、pomp は `{kick,snare,hat}` で、engine の「文字数で小節を等分」形式と合わず拍がずれていた（pomp は "[object Object]" の O をオープンハットとして鳴らしていた） |
| rhythm_engine の増減値を `+0.75 / +0.65 / −0.25 / 空打ち−0.15 / 10コンボ+1` に変更 | 企画書値だと全PERFECTで約12秒で100到達。node シミュレーション（偽の時計）で 全PERFECT 46〜52秒 / 上手め 52〜61秒 / 普通 65〜74秒(多くは救済) / 放置 75秒 |
| 回顧の叫びは候補ごと（`AT.TEXTS.recallShout`、recall と同じ添字） | 下書きで候補ごとに叫びが違うため |
| タイトルは「1回目のタップで音を解禁しパーセルを鳴らす → 2回目で開始」 | ブラウザはユーザー操作前に音を出せないため |
| 疾走中のレーンは画面最下部(y162〜180)、R1/R3 の主人公の接地は y160 | R1 の接地 168 だとレーンに主人公が隠れたため |
| 回顧の曲は全ラウンド `tell_slow`（こもらせる） | 静かな曲が tell_slow しかないため |

## ユーザーが耳と目で確認すべき項目
### 耳
1. 各曲（テル/威風堂々/歓喜の歌/パーセル風）の旋律が原曲として聞こえるか（全曲「未照合」）。
2. 疾走中のキックとノーツ（判定線の光）が合っているか、叩いた感覚とPERFECTがずれないか（出力遅延の実機ずれ）。必要なら `AT.audio.latency` を調整。
3. 威風堂々のドラム（4つ打ち＋2・4拍スネア）が正しく聞こえるか（統合で書式変換したため）。
4. 回顧中のこもった音（lowpass 400Hz）と tell_slow の雰囲気、叫びの効果音。
5. 襲来の心拍音（キック2連）、白光で無音になる落差。
6. 判定音（PERFECT/GOOD/MISS）がうるさすぎないか。
### 目
1. 疾走の長さ（目安 全PERFECT約50秒・普通60〜70秒）が長すぎ/短すぎないか。
2. レーンの見やすさ（ノーツの色・大きさ、8分ノーツ＝白の小さい菱形）。
3. 速度70%以上の残像、90%以上の色相回転が気持ち悪すぎないか。
4. 回顧の青黒オーバーレイの濃さ、文字の読みやすさ、叫びの大きさ。
5. 渦（突入）の見え方、白光→夜道のフェード。
6. 結末のランク分岐（S: 窓に明かり＋停止 / A: 停止 / B: 鍵を探してもぞもぞ / C: 家の前を通り過ぎる）と文字配置。
7. 帰り道15秒×3回が長すぎないか（調整は scenes.js の `walk.dur`）。
