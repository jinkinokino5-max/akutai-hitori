# 統合メモ（2026-10-30 疾走パート刷新の統合 / 統合担当 Opus）

旧版（2026-10-29 リズム版の統合）の内容は git 履歴（このファイルの前の版）を参照。

## 現在の状態
- `output/` をローカルサーバ（例: `python -m http.server` を output/ で）で開くと、
  タイトル → R1〜R3（帰り道→襲来→回顧→渦→**疾走（刀で斬って闇から逃げる）**→白光）→ 結末 → タイトル が通しで遊べる。
  疾走で闇に呑まれると 呑まれる演出 → ゲームオーバーの結末 → タイトル。
- **音は fetch で読むので file:// では無音**（絵とゲームは動く）。GitHub Pages 等にも置けるよう相対パス `audio/xxx.mp3`。
- 読み込み順: data(texts, rounds) → core/input → audio_engine → slash_engine → art_common → art_r1〜r3 → art_obstacles → ui → scenes → main。
- リズム版（rhythm_engine.js, songs*.js, rhythm_test.html）は `archive/リズム版/` へ移動。

## 主な統合判断（理由つき）
| 内容 | 理由 |
|---|---|
| 逃げ切りは **曲の時計**（`AT.audio.musicElapsed()`）が `曲長 − endPad` に達したとき。曲が鳴っていなければ同じ秒数の経過時間。engine の `config.duration` は疾走中だけ外し（1e9）、時刻が来たら `duration = S.time` にして engine に 'escaped' を出させる | engine の時間はヒットストップ中に止まる。実測: 曲39.5秒の時点で engine 35.8秒（上手いプレイ）。40秒固定だと曲が先に終わって無音で走ることになる。engine の定数・コードは変えていない |
| endPad: R1/R2 0.5秒、R3 1.0秒 | MP3 末尾0.5秒はフェード済み。ブラウザで decode した波形の0.5秒ごとの RMS: R3 は 38.5秒以降 −32→−45dB（最終和音の減衰）なので1秒前、R1（差し替え後のファンファーレ版）は最後まで −20dB台＝フェードで切れる曲なのでフェード頭、R2 は最後の0.5秒だけ −33dB |
| 乗り手の左端 x = bikeX−17 = 93 | 自転車の前輪の先（左端+23）が engine の衝突線 bikeX+bodyX=116 と重なる。刀の軌跡（左端+22 中心、半径20/JUST 24）の先端 135/139 が engine の間合い 134 とほぼ一致 |
| 障害物の描画位置 = engine の x − info().hit.x | engine の x は実体の前縁、drawObstacle の x はスプライト左端のため |
| 斬った障害物は scenes 側の `cuts` で 0.6秒崩す。衝突した障害物は破片(GOOD相当)を散らして消す | engine は処理済みを即削除するため。衝突の崩し方は art 側に無いので破片で代用 |
| R3 の廊下には疾走距離(px)の 1/16 を渡す | R3 の dist は「奥行き」の単位。旧版は px をそのまま渡しており、速度50で絵本来の前進速度とほぼ同じになる比を選んだ |
| 残像はコンボ5以上で強くなり、色相回転はコンボ20以上 | プラン§2-2「コンボが続くほど残像・色相回転が強くなる」。旧版は速度70/90%で発動 |
| 結末ランク: 3ラウンド平均の `AT.slash.result().score`、しきい値 S≥85 / A≥72 / B≥60 | 下の「検証」参照。初期値 65/40 では C が出ない |
| 呑まれたときの一言は、そのラウンドの回顧文の最後の行 | プラン§6 の未決事項。回顧で読んだばかりの言葉が返ってくる方が刺さる。専用文は増やさない |
| 音は **WebAudio（fetch→decodeAudioData）**。HTMLAudio は使わない | iOS Safari は HTMLAudio の volume を無視し、同時発音・ローパス接続に癖がある。WebAudio なら効果音の重ね・クロスフェード・ローパス・ループ点を一つの仕組みで扱える |
| 起動時は MP3 のバイト列だけ prefetch、AudioContext は最初のタップで作って decode | ユーザー操作前に AudioContext を作ると Chrome が警告する。iOS 17+ は `navigator.audioSession.type='playback'` で消音スイッチ中も鳴らす |
| 使い終わった曲の decode 結果は捨てる（title は帰り道で、前ラウンドの曲は次の帰り道で release） | decode 後は約0.35MB/秒（タイトル177.6秒で約62MB）。スマホのメモリ対策。バイト列は残るので結末で再 decode できる（実測で decode 約1.8秒の遅れ） |
| 闇のループは loopStart/End で先頭末尾0.05秒を飛ばす。音量 = 0.08 + 0.92×(dark/限界)² | manifest の注記（MP3 先頭/末尾に約25msの無音）。遠いと小さく、1/3 に近づくと急に大きく |
| 効果音の音量: 斬撃0.35・手応え0.5(JUST)/0.35(GOOD、ピッチ少し上)・衝突0.85・白光1.0・惰性0.35 | 依頼の「斬撃・手応えは控えめ、衝突はやや強め、白光は大」。聴感は未確認 |
| 合成音は心拍・叫びの打楽器と効果音の予備（録音がまだ decode されていないとき）だけ残した。合成曲のシーケンサ（拍・BPM・小節）は削除 | 曲データ songs*.js を archive へ移したので死んだ参照になるため。旧実装は archive/リズム版/ と git 履歴にある |
| 合成の打楽器は BGM 用バスではなく効果音バスに出す | 回顧の叫びのキックがローパスでこもらないように（旧版はこもっていた。違和感があれば戻す） |
| rounds.js の music は `{run, recall, runLen, endPad}`、bpm は削除。AT.MUSIC / AT.SONGS は廃止 | 新方式では曲の id だけで足りる。runLen は音なしのときの長さ（manifest の duration と同じ値） |

## ユーザーが耳と目で確認すべき項目
### 耳
1. 疾走の終わりと白光が合っているか（R1 はフェードで切れる版、R3 は最終和音の1秒前で白光）。ずれる場合は `data/rounds.js` の `endPad` を調整。
2. 効果音の音量バランス（斬撃・手応え・衝突・白光）。調整は `audio_engine.js` の `SFX_VOL`。
3. 闇のざわめきの大きさ（遠いとき聞こえすぎ/近いとき足りない）。
4. 回顧の曲（各回の静かな区間）がこもった状態で雰囲気に合うか、ループの継ぎ目。
5. 呑まれた後の無音と、惰性の回転音の小ささ。
6. タイトル・結末の title.mp3、帰り道で1.5秒かけて消える感じ。
### 目
1. 刀の間合い: 障害物が光ったら斬れる（光る範囲＝間合い）。JUST の取りやすさ。
2. 闇の幅（1/3 で呑まれる）が近すぎ/遠すぎないか。放置で約10秒で呑まれる。
3. 呑まれる演出の各尺（覆う0.6・一言2.6・引く0.8・自転車3.5秒）、一言の大きさ。
4. ゲームオーバーの結末文（下書き）と、無人の自転車で終わる絵でよいか。
5. 結末ランクの分かれ方（S/A/B/C）と成績表示の項目。
6. コンボ時の残像・色相回転・高速時の画面揺れが気持ち悪すぎないか。
